# Solid-native references

A survey carried out on 2026-11-19, after deciding that Menhir follows Solid 2.0 idioms first and uses Base UI as a behaviour reference only ([PLAN.md](../../PLAN.md) section 8). It records what Kobalte, solid-primitives and corvu offer: how a test is written, how a problem is solved in Solid, and where their coverage stops.

## Method and limits

- Read through the GitHub API on 2026-11-19 (Kobalte `solid2` at `ba6b1df`, solid-primitives and corvu `main`). Base UI tests were counted from a sparse clone of tag `v1.9.0`. Nothing was installed, built or run.
- Test counts are a regex over `it(` and `test(` calls, including `.each`, `.skip`, `.todo` and `.skipIf`. Base UI's count leaves out cases generated by `describeConformance`. Treat the counts as an order of magnitude.
- Whether Kobalte's `solid2` tests pass, and whether the branch will be released, was not determined.

No test files on `solid2` cover dismissal, focus trap, scroll lock or hover intent. Kobalte's `solid2` gets most of that behaviour from solid-primitives (below), whose packages do have tests.

What this means:

- **Kobalte is the model for how a test is written.** Its tests are already idiomatic Solid 2.0. Its cases are a good starting set for Switch, Checkbox, Separator and Progress.
- **Base UI supplies most of the cases for Collapsible, Tabs, Dialog, Popover and Tooltip.** Kobalte has few or no tests for these. Each Base UI case is rewritten in Kobalte's style against Menhir's API, not ported mechanically.
- **The floating layer's Solid test source is solid-primitives.** It has suites for the focus trap, scroll lock, outside interaction and hiding content outside a modal. Positioning and hover intent have no Solid tests; use the WAI-ARIA patterns and Base UI's cases.

### How the tests are written

- `render(() => <Switch.Root>…</Switch.Root>)` from `@solidjs/testing-library`, with `getByRole` and `getByTestId` queries and `fireEvent`. `jest-dom` matchers.
- Controlled state is tested with a static prop plus a `vi.fn()` change handler. None of the twelve files above calls `createSignal`, so none changes a prop after rendering. Menhir's tests do that through a signal and `flush()` (PLAN.md section 7).
- `@kobalte/tests` holds a few helpers: `installPointerEvent`, `triggerTouch`, `createPointerEvent`, `setupMatchMediaMock`.
- jsdom only, `globals: true`, `isolate: false`. `packages/core/test-setup.ts` registers `cleanup` in `afterEach` again, because with `isolate: false` the testing library's own registration runs only in the first file of each worker. It also stubs `scrollIntoView`. Menhir's `createRenderer` registers cleanup for a related reason (PLAN.md section 7).
- SSR tests are `*.ssr.test.tsx` files run by `vite.ssr.config.ts` (`generate: "ssr"`, `environment: "node"`). They call `renderToString` and assert on attributes in the HTML. Only `text-field` has one so far. Menhir's `hydrate` project goes further: it also hydrates.

### How components are built

- Polymorphism: an `as` prop, rendered through `Dynamic` by a `Polymorphic` component (`packages/core/src/polymorphic/polymorphic.tsx`), with `omit(props, "as")`.
- Ids: parts derive ids from the root id (`${rootId}-input`) at creation time, so the server HTML is already linked without effects. The `text-field` SSR test checks this. `create-register-id` registers ids on the client.
- State primitives: `create-toggle-state`, `create-disclosure-state`, `create-controllable-selection-signal`.
- Dependencies: `@floating-ui/dom`, `@internationalized/number`, and 17 solid-primitives packages, among them `controlled-signal`, `focus`, `scroll`, `interaction`, `presence`, `props` and `refs`. Its own `dismissable-layer` and `popper` sit on top of these. This shared stack is part of why Kobalte is heavy; Menhir reads it for behaviour and keeps its own dependencies near zero (PLAN.md section 6, rule 5).

## solid-primitives

`main` depends on `solid-js` 2.0.0 and `@solidjs/web` 2.0.0, and the packages below are released for 2.0 (`@solid-primitives/focus` 1.0.0, 2026-11-17). Kobalte's `solid2` branch is built on them. Packages worth comparing against when building `core` and `floating`, with the number of tests in each package's main test file:

| Package             | Primitives                                           | Tests | Menhir issue |
| ------------------- | ---------------------------------------------------- | ----- | ------------ |
| `focus`             | `createFocusTrap`, `createFocusRestore`, `autofocus` | 57    | #27          |
| `scroll`            | `createPreventScroll`                                | 16    | #28          |
| `interaction`       | `createInteractOutside`                              | 28    | #26          |
| `interaction`       | hide outside (`hide-outside.test.ts`)                | 26    | #27          |
| `presence`          | `createPresence`, for enter and exit animations      | 42    | popups       |
| `controlled-signal` | `createControllableSignal`                           | 36    | #13          |

Each of these packages also has a `server.test.ts`, and `controlled-signal` and `a11y` have hydration tests.

- `controlled-signal`'s README passes `value` as an accessor (`props.value` typed `Accessor<number>`), which conflicts with rule 1 in AGENTS.md (pass values, not accessors). Treat it as a reference for the behaviour, not for the signature.
- Also relevant: `keyboard`, `event-listener`, `refs`, `props`, `a11y`.
- Using them as dependencies would break rule 5 in PLAN.md (near-zero dependencies) unless it is changed deliberately. By default, read them and their tests; do not install them.
- `scripts/test-utils/hydration-harness.ts` (`renderHydrationRoundTrip`) renders through `renderToString` and `hydrate` from the built package. `packages/a11y/test/hydration.test.tsx` uses it to catch id mismatches between server and client.

## corvu

- No test files on `main`.
- The released code is Solid 1.x, and the Solid 2.0 branch was abandoned early. Read it for API design and decomposition, not as code to adapt.
- It splits expensive behaviour into standalone packages: `solid-dismissible`, `solid-focus-trap`, `solid-prevent-scroll`, `solid-presence` and `solid-list`. That matches rule 6 in PLAN.md (expensive behaviour is a part, not a flag), and the packages map onto issues #26, #27, #28 and the list navigation in #36.
- Polymorphism is a `Dynamic` component in `packages/utils/src/dynamic`.
